What is صِلَة? · The Linguistics of Continuity

Developers often ask: What does the name Sila (صِلَة) mean?

In classical Arabic lexicography, صِلَة (Sila) derives from the root وَصَلَ (wasala) — signifying union, connection, and unbroken continuity, the direct antithesis of rupture, abandonment, or separation (الوَصْلُ ضِدُّ الفَصْلِ والهجران). Documented across fifteen centuries of scholarship, Sila articulates the foundational engineering ethos of this system:

The Unifying Bridge الرابط بين الشيئين
«إِنِّي رَأَيْتُ أَنْ أَبْنِيَ مِصْرًا بَيْنَ هَذَيْنِ البَحْرَيْنِ، يَكُونُ صِلَةً بَيْنَ المَشْرِقِ وَالمَغْرِبِ»
— وهب بن مُنَبِّه، كتاب التيجان في ملوك حِمْيَر (114هـ / 732م)
In Sila: AI coding assistants operate in isolated silos. Sila serves as the cross-harness bridge uniting Claude Code, Devin, OpenCode, Codex, and Antigravity into one shared ground truth.
Completing Meaning صِلَة الموصول
«الجُمْلَةُ الَّتِي تَقَعُ بَعْدَ الاِسْمِ المَوْصُولِ؛ لِتَتْمِيمِ مَعْنَاهُ، وَلَا يَتِمُّ مَعْنَاهُ إِلَّا بِهَا.»
— سيبويه (180هـ / 796م) & الخليل بن أحمد الفراهيدي (175هـ / 791م)
In Sila: An AI agent entering a codebase without prior history is like a relative pronoun without its clause: incomplete and ambiguous. Sila provides the essential context that makes the prompt whole.
Unbroken Cadence الاستمرار بلا انقطاع
«الصِّلَةُ: رَبْطُ البَيْتِ بِالبَيْتِ، وَالمِصْرَاعِ بِالمِصْرَاعِ مِنْ غَيْرِ مَقْطَعٍ وَلَا تَنَفُّسٍ.»
— الحسن بن أحمد الكاتب، كمال أدب الغناء (625هـ / 1228م)
In Sila: Session limits, compaction, and tool-hopping fracture developer flow. Sila guarantees unbroken memory across days, turns, and CLI harnesses.
The Lightweight Cord صِلَة الحبل
«لَا تَحْقِرَنَّ مِنَ المَعْرُوفِ شَيْئًا، وَلَوْ أَنْ تُعْطِيَ صِلَةَ الحَبْل»
— مسند الإمام أحمد ابن حنبل (11هـ / 632م)
In Sila: A durable cord binding complex systems together: pure-Go, 14 MB standalone binary, zero background daemons, and zero CGO dependencies.

4-Tier Intent Memory Architecture

Sila organizes knowledge across four distinct tiers of cognitive latency, retrieval scope, and durability:

Tier Intent Storage Layer Retrieval Latency Primary Command
1. Hot Session Handoffs, Active Task Checklists, Git Branch handoffs table < 5 ms sila handoff
2. Warm Architectural Invariants, Directives, Solution Lessons, MADR Records memos, lessons, adrs < 10 ms sila memo, sila lesson, sila prime
3. Cold Cross-Tool Session Transcripts, Distilled Claims, Provenance SQLite FTS5 (messages_fts, facts) < 30 ms sila search, sila recall, sila dream
4. Reference Attached Reference Docs, Crawled Web Specs docs_fts < 25 ms sila doc, web-search

Sila Trigger Contract (Agent Operating Loop)

The standard operating rhythm for AI coding assistants working in a Sila-enabled repository:

Lifecycle Step Command Purpose
1. First touch in a repo sila salam Front door: prints the working loop, live heal status, ready goals, active claims, and last handoff.
2. Task start sila heal Brings repo current: rules, plugin, MCP config; then run sila prime and sila goals ready.
3. Briefing sila prime Turn 0 context briefing with handoff state, architectural invariants, facts, and context budget.
4. Stuck on error/package sila recall "<symptom>" Recalls cross-project prior fixes before web search or speculative trial-and-error.
5. Problem solved sila lesson "<symptom>" --cause=... --fix=... --files=... / sila lesson distill --save Records or auto-distills grounded solution lessons into store for future agent recall across all harnesses.
6. Decision made sila memo "<directive>" Records immutable architectural invariant or project constraint.
7. Session conclusion sila handoff "<summary>" --open=... & sila sync Hands state to the next session and synchronizes new transcripts into SQLite store.

sila standup · Human Morning Briefing

In Sila v0.7.0, the semantic division between human developers and AI coding agents is cleanly decoupled. sila standup is the dedicated executive morning debriefing for human developers.

☀️ Human-First Focus
Your daily briefing: architectural decisions recorded, commits shipped, open action items from handoffs, and unverified claims needing human review.
🌐 Workspace-Wide Horizon
With --global (or -g), aggregates and tags activity across all workspace projects: [sila], [web], [api].

Human Standup Usage

Natural Time Windows & Global Workspace 
# Check what happened in the current project in the last 5 hours
sila standup last 5h

# View cross-project standup across ALL repositories in your workspace
sila standup last 5h --global

# Shorthand for global standup over the last 2 days
sila standup -g last 2d

# Lookback units supported: m (minutes), h (hours), d (days), w (weeks), mo (months)
sila standup last 30m
sila standup last 1mo

sila digest · Multi-Agent Activity Ledger

sila digest is designed for AI coding agents and automated CI/CD pipelines. It tracks cross-tool multi-agent session occurrences, user prompts, assistant replies, and drill-down inspection commands.

🤖 Agent Activity Tracking
Inspect recent sessions across Codex, Claude Code, Devin, OpenCode, and Muse without needing a search term or manual handoff.
⚡ Token-Optimized Serialization
Supports Token-Oriented Object Notation (--toon) to save ~40% tokens when passing cross-session history to sub-agents.

Agent Digest Usage

Agent Activity & Token-Optimized Output 
# Multi-agent session activity summary (last 24h)
sila digest --activity

# Token-Oriented Object Notation (TOON) for agent ingestion (~40% fewer tokens)
sila digest --activity --toon

# Machine JSON for automated CI/CD pipelines
sila digest --activity --json

CLI Command Manual

sila salam · Agent Front Door

The standard front door for agents entering a repository. Prints the complete working loop together with live next steps: heal findings, ready goals, active claims, and the latest session handoff. Aliases: hi, hello, merhaba.

Examples
# Standard agent entry point at session start
sila salam

# Machine-readable format for agent harnesses
sila salam --json

# Friendly international aliases
sila hi
sila merhaba

sila do & sila ccli · Conversational CLI Dual-Syntax Engine

Deterministic grammar-lowered convenience phrases across 76 phrase families and 6 domains (zero LLM calls). Canonical commands always take precedence (canonical-first); overlapping phrases run explicitly via sila do "..." with 3-tier safety enforcement and secret detection.

Examples
# Non-colliding conversational phrases auto-rewrite to canonical commands
sila remember error "database is locked"
sila show ready goals

# Overlapping phrases execute explicitly via sila do
sila do "sync rules"
sila do "release goal my-goal"

# Inspect grammar lowering, safety tier, and canonical argv without side effects
sila ccli explain save memo "use WAL mode"
sila ccli list --domain=memory
sila help phrases

sila heal · Repository Self-Healing

Brings a repository current in a single idempotent command: merges duplicate path registrations, provisions canonical agent rules, hooks, MCP configs, OpenCode plugin, and completion goals, prunes closed-goal claims, releases stale locks, and reports residual judgment steps.

Examples
# Self-heal current repository into Sila
sila heal

# Preview healing changes without writing files
sila heal --dry-run

# Structured JSON output
sila heal --json

sila prime · Instant Context Briefing

Generates a Turn 0 context briefing for incoming agents, containing active handoff items, architectural decisions, distilled facts, file-referenced claims (shown under their own heading, never as facts), and verified repository runbook commands with context budget metering.

Examples
sila prime
sila prime --project=my-app
sila prime --toon    # Token-optimized format

sila recall & sila lesson · Solved-Before Knowledge Recall & Lessons

Find prior cross-project resolutions before web search or speculative trial-and-error: checks structured lessons first, then grounded facts and verbatim transcripts. Solved problems are persisted as first-class lessons with symptoms, root cause, fix, and grounded file evidence.

Examples
# Recall past solutions for an error or symptom across all projects
sila recall "SQLITE_BUSY database is locked"

# Semantic cross-project recall with System One reranking
sila recall "drizzle D1 migration error" --semantic

# Record a solved problem lesson with verified cause, fix, and files
sila lesson "SQLITE_BUSY on concurrent writes" \
  --cause="Missing WAL mode PRAGMA" \
  --fix="Enable PRAGMA journal_mode=WAL and busy_timeout=5000" \
  --files="internal/store/db.go"

# List recorded lessons in the repository
sila lesson list

# Proactively distill lesson candidates from session transcripts
sila lesson distill
sila lesson distill --save

sila search · Transcript & Omni Search

Full-text search (SQLite FTS5) across raw conversation transcripts from all tools, with multi-turn surgical unrolling via expand, and optional semantic reranking via --semantic with strict immutable authority tiers.

Examples
# Search raw transcripts
sila search "drizzle migration"

# Hybrid multi-tier search across facts, transcripts, git, and docs
sila search "auth race condition" --omni

# Blended omni-search with optional semantic reranking
sila search "auth race condition" --omni --semantic

# Unroll 5 conversation turns around message ID 42
sila search expand 42 --window=5

sila dream & sila verify · Knowledge Lifecycle

Distills raw assistant session messages into verified claims, checks referenced files on disk, and reconciles drift. Physical disk existence checks are decoupled from semantic contradiction audits (--semantic).

Examples
# Query claims whose referenced files exist on disk
sila dream query auth --refs-exist

# Re-verify referenced repository files on disk
sila verify

# Dry-run preview of reconciliation changes
sila dream reconcile --dry-run

# Run optional semantic contradiction audit during reconciliation
sila dream reconcile --semantic

sila memo & sila adr · Architectural Decisions

Record permanent architectural directives and living Markdown Architectural Decision Records (MADR).

Examples

sila memo "Always use pure-Go SQLite with modernc.org/sqlite" --files=go.mod

# Scaffold a new living Architecture Decision Record
sila adr new "Adopt TOON Serialization" --deciders="jad,agent"

sila handoff · Session Continuity

Examples

sila onboard · Legacy Task & Repo Onboarding

Inventories legacy task surfaces (agent brain directories, markdown task lists, scaffolds), provisions canonical Sila rules, hooks, and MCP configurations, and verifies active Sila participation with strict health checks.

Examples
# Onboard the current repository into Sila
sila onboard

# Verify onboarding health strictly across the workspace
sila onboard check --strict

# Convert legacy markdown task list into tracked Sila goal package
sila onboard --convert-tasks --from=TODO.md --review

sila doc · Documentation Engine & Offline Portal Server

Attach reference documents, crawl entire documentation websites into FTS5, perform live web doc searches, or launch the zero-dependency pure-Go local documentation portal with sila doc serve.

Examples
# Serve this offline documentation portal with zero external dependencies
sila doc serve

# Serve on a custom port without auto-opening browser
sila doc serve --port=8080 --no-open

# Recursively crawl documentation into local FTS5 index
sila doc https://docs.anthropic.com/en/docs/ --crawl --depth=2

# Live web search with automatic local indexing
sila doc web-search "sqlite fts5 ranking" --auto-ingest

sila export rules & sila agents · Rule Synchronization & Instruction Review

Compiles project memory, invariants, and domain rules into target tool formats (CLAUDE.md, .cursorrules, .windsurfrules, or AGENTS.md). Uses the Hub-and-Spoke compiler to preserve user-authored sections while detecting drift with SHA-256 validation. Also supports previewable instruction reviews from multi-agent session friction via sila agents review and sila export rules --review with project or global scope consent.

Examples
# Export project memory into a specific agent rules file
sila export rules --target=claude --out=CLAUDE.md

# Verify rule consistency across all detected tools
sila agents check

# Deploy canonical rules across all detected AI tools
sila agents sync

# Preview proposed rule updates from session friction (preview only; writes nothing)
sila agents review claude --scope=project

# Review proposed export changes before modifying rules
sila export rules --review --target=claude

sila sync & sila ingest · Incremental Ingestion

Single-pass ingestion and claim distillation. Reads new session logs across all installed AI harnesses with watermarks, content hashing, deduplication, and automatic background self-vacuuming.

Examples
# Incremental sync across all installed AI tools
sila sync

# Preview changes without modifying the SQLite store
sila sync --dry-run

# Run full workspace sync across all registered repositories
sila sync --global

# Ingest a specific tool only
sila ingest claude-code

sila doctor, sila vacuum & sila backup · Health & Storage Maintenance

End-to-end SQLite integrity verification, FTS5 index reconciliation, orphan cleanup, stale MCP server detection, and always-load context budget analysis. sila vacuum defragments pages, sila backup creates live snapshots, and sila storage reports on-disk footprints.

Examples
# Run 8-point system health check
sila doctor

# Automatically repair FTS5 indexes and clean orphaned occurrences
sila doctor --repair

# Check database fragmentation metrics without modifying data
sila vacuum --stats

# Write safe VACUUM INTO backup snapshot during active writes
sila backup

# Inspect on-disk storage footprint of Sila and source tools
sila storage

sila cloud · Cloudflare D1 Edge Bridge & Inbound Digestion

Bridges distributed conversation mailboxes running on Cloudflare Workers and D1 SQLite directly into local stores. sila cloud status probes edge connectivity with graceful offline fallback; sila cloud pull drains pending conversations, parses Markdown turns, commits them into local SQLite with SHA-256 content deduplication, and atomically acknowledges items at the edge. A strict consent gate ensures zero network calls unless explicitly configured.

Examples
# Probe edge health, pending mailbox items, and last sync timestamp
sila cloud status

# Drain, digest, and acknowledge pending inbound conversations
sila cloud pull

# Pull up to 20 conversations scoped to a specific project
sila cloud pull --limit=20 --project=sila

# Inspect status in machine-readable JSON format
sila cloud status --json

sila goals & sila crew · Multi-Agent Coordination

Closed-loop multi-agent goal attribution and worktree coordination. sila goals audits project roadmaps, manages claim locks to prevent collisions, and matches Git commits to close goals. sila crew supervises autonomous sub-agents running in disposable Git worktrees inside tmux sessions.

Examples
# View local project goal roadmap and pending items
sila goals

# View cross-repo multi-project goals matrix across workspace
sila goals --global

# Claim a goal to prevent agent collisions
sila goals claim my-goal --agent=agy

# Spawn an autonomous agent crewmate in a tmux sandbox
sila crew spawn agy my-goal

# Inspect crewmate liveness with zero-token background supervision
sila crew supervise

sila gate · Engineering Discipline & Sentry

Runs deterministic engineering discipline checks: unit tests with -race, gofmt formatting, CHANGELOG.md currency, binary freshness, documentation coverage, and semantic diff sentry with local tail risk detection and full secret redaction.

Examples
# Fast pre-commit discipline check (tests, format, binary, docs, sentry)
sila gate

# Complete sandboxed worktree pipeline
sila gate pipeline

# Emergency bypass
SILA_SKIP_GATE=1 git commit -m "emergency fix"

Verifies the 12-moment adoption trigger catalog (sila/adoption-case/v1) across surface availability, MCP profile exposure, and scripted agent execution with sila eval adoption, or runs recursive contrastive harness evaluation with sila eval recurse.

Examples

sila eval adoption

sila eval adoption --json

sila feedback & sila vision · Feedback Ledger & Strategic Vision

Closed-loop ticket ledger for agent observations, friction tips, and ideas. sila vision compiles the living VISION.md strategic North Star and executes tournament proposal triage against invariants and non-goals.

Examples

sila vision triage

Security, Privacy & Offline Contract

No Telemetry. Zero Cloud Dependencies. 100% On-Disk.
Sila never transmits your code, prompts, or decisions to external servers. It runs entirely on your local machine using pure Go and an embedded SQLite database.
  • Read-Only Source Harness Access: All source tool stores are opened strictly with mode=ro. Sila never writes to another tool's internal database files.
  • Private File Permissions: Sila's database is initialized with 0700 directory and 0600 file permissions.
  • Zero Background Daemons: Sila runs when you or your agent invokes it. It does not spawn silent background daemons or burn CPU in the background.

Settled Architecture Decisions

Pure Go SQLite
Built with modernc.org/sqlite with CGO_ENABLED=0. Completely self-contained binary across Linux, macOS, and Windows.
Uncompressed Binary
UPX was rejected because saving ~9MB download cost ~354ms decompression on every CLI invocation. Instant startup won.
Hyrum's Law Contract
CLI flags and MCP tool signatures are public contracts. No flag or tool is removed without deprecation notice.
